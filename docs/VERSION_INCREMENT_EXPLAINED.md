Version Increment - Complete Explanation

This document explains EXACTLY which files control version numbers and why all of them need to be updated.

================================================================================
THE PROBLEM
================================================================================

EAS Build and native build systems read version numbers from MULTIPLE places:

1. app.json - Expo/React Native config (what we think controls everything)
2. iOS native files - Xcode reads from these directly
3. Android native files - Gradle reads from these directly

If these don't match, you get build errors or wrong versions in the store.

================================================================================
FILES THAT CONTROL VERSION NUMBERS
================================================================================

### iOS Version Numbers (3 places):

1. **app.json**
   - `expo.version` → User-facing version (1.0.6)
   - `expo.ios.buildNumber` → Build number (4)

2. **ios/DailyVibe/Info.plist**
   - `CFBundleShortVersionString` → User-facing version (1.0.6)
   - `CFBundleVersion` → Build number (4)
   - **Xcode reads this directly!**

3. **ios/DailyVibe.xcodeproj/project.pbxproj**
   - `MARKETING_VERSION` → User-facing version (1.0.6) - appears 2x (Debug/Release)
   - `CURRENT_PROJECT_VERSION` → Build number (4) - appears 2x (Debug/Release)
   - **Xcode build system uses this!**

### Android Version Numbers (2 places):

1. **app.json**
   - `expo.version` → User-facing version (1.0.6)
   - `expo.android.versionCode` → Build number (10)

2. **android/app/build.gradle** (generated by expo prebuild)
   - `versionName` → User-facing version (1.0.6)
   - `versionCode` → Build number (10)
   - **Gradle reads this directly!**

### Package Version:

1. **package.json**
   - `version` → Should match app.json version (1.0.6)

================================================================================
WHY EAS BUILDS FAIL
================================================================================

When you run `eas build`:

1. EAS reads app.json ✅
2. EAS runs `expo prebuild` which generates native files
3. BUT if native files already exist, they might not be regenerated
4. Xcode/Gradle read from the EXISTING native files ❌
5. Version mismatch → Build fails or wrong version submitted

================================================================================
THE SOLUTION
================================================================================

The increment-version.sh script updates ALL files:

1. ✅ app.json (version, ios.buildNumber, android.versionCode)
2. ✅ package.json (version)
3. ✅ ios/DailyVibe/Info.plist (CFBundleShortVersionString, CFBundleVersion)
4. ✅ ios/DailyVibe.xcodeproj/project.pbxproj (MARKETING_VERSION, CURRENT_PROJECT_VERSION)
5. ✅ android/app/build.gradle (versionName, versionCode) - if exists

This ensures EVERY file that EAS/Xcode/Gradle might read has the correct version.

================================================================================
HOW TO USE
================================================================================

Before every build:

```bash
npm run increment-version
```

Or it runs automatically:
```bash
npm run build:ios      # Increments, then builds
npm run build:android  # Increments, then builds
```

================================================================================
VERIFICATION
================================================================================

After running increment-version, verify all files match:

1. Check app.json:
   ```bash
   grep '"version"' app.json
   grep 'buildNumber' app.json
   grep 'versionCode' app.json
   ```

2. Check iOS Info.plist:
   ```bash
   grep 'CFBundleShortVersionString' ios/DailyVibe/Info.plist
   grep 'CFBundleVersion' ios/DailyVibe/Info.plist
   ```

3. Check iOS project.pbxproj:
   ```bash
   grep 'MARKETING_VERSION' ios/DailyVibe.xcodeproj/project.pbxproj
   grep 'CURRENT_PROJECT_VERSION' ios/DailyVibe.xcodeproj/project.pbxproj
   ```

4. Check Android (if exists):
   ```bash
   grep 'versionName' android/app/build.gradle
   grep 'versionCode' android/app/build.gradle
   ```

All should show the SAME version numbers!

================================================================================
TROUBLESHOOTING
================================================================================

Issue: "Build number already exists"
Solution: Run increment-version.sh again - it increments all files

Issue: "Version mismatch error"
Solution: Check all files listed above - one might not have been updated

Issue: "Script doesn't update Xcode project"
Solution: Make sure you're using the correct sed command for your OS (macOS vs Linux)

Issue: "Android versionCode not updating"
Solution: Run `expo prebuild` first to generate android folder, then increment
